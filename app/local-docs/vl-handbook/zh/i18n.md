# 国际化

Vellum 原生支持多语言文档。语言在站点级别配置，对每个仓库都生效。

## 站点级语言配置

```json
{
  "site": {
    "defaultLocale": "en",
    "locales": [
      { "code": "en", "label": "English", "prefix": "" },
      { "code": "zh", "label": "中文", "prefix": "zh" },
      { "code": "ja", "label": "日本語", "prefix": "ja" }
    ]
  }
}
```

- `code` 是语言代码（用作 i18n 查询 key，也是非默认语言的默认源目录名）。
- `label` 在语言选择器里显示。
- `prefix` 是 URL 段。空字符串表示该语言位于每个仓库的根——
  通常给默认语言用。

读到 `/zh/repo/getting-started` 的人正在看 `repo` 仓库内
`getting-started` 的 `zh` 版本。

## 每个仓库的内容布局

默认语言的页面直接位于 `docsRoot` 下。其他语言的页面位于
`{docsRoot}/{code}/` 下，目录名取语言的 `code`，而不是 URL 前缀。

```
docs/
  index.md                    # en（默认语言）
  getting-started.md
  zh/
    index.md                  # zh
    getting-started.md
  ja/
    index.md
    getting-started.md
```

::: note
你不必翻译每一页。读到 `/zh/repo/missing-page` 时会得到 404，
而不是回退到英语版——这样维护者一眼就能看到缺失的翻译。
:::

### 其他布局

有些仓库给每个语言都建了单独的目录，包括默认语言。用仓库上的
`localeDirs` 把语言代码映射到对应目录：

```json
{
  "slug": "nextbridge",
  "docsRoot": "",
  "localeDirs": { "en": "en", "zh": "zh" },
  "landingPage": "v0.4"
}
```

```
en/
  v0.4/
    index.md                  # /en-US/nextbridge/v0.4
    getting-started.md        # /en-US/nextbridge/v0.4/getting-started
zh/
  v0.4/
    index.md                  # /zh-CN/nextbridge/v0.4
index.md                      # 不属于任何语言，不会被提供
```

不在任何语言目录下的文件不属于任何语言，不会被提供。按目录写的绝对
链接，例如侧边栏、hero 按钮或页面里的 `/en/v0.4/rules`，会解析到
仓库内部。

当文档根目录没有真正的首页时（比如按目录分版本的文档），
`landingPage` 会把仓库根 URL 重定向过去：`/en-US/nextbridge` 跳到
`/en-US/nextbridge/v0.4`。

## 路由

每个页面 URL 都以语言开头：

```
/{localePrefix}/{repoSlug}[/{pagePath}]
```

构建会从每种语言自己的源目录渲染该语言的页面，所以同一个 `pagePath`
（"getting-started"）在 `en` 下来自 `docs/getting-started.md`，在 `zh` 下来自
`docs/zh/getting-started.md`。主页仓库的首页就是位于 `/{localePrefix}` 的落地页。

当每种语言都有前缀时，`/` 本身没有页面。它在浏览器里选择语言：先看读者之前的
选择（语言选择器写入的 `vellum-locale` cookie），再看浏览器的语言，最后是
`defaultLocale`。没有 JavaScript 时会去默认语言。（前缀为空的语言，其落地页
就在 `/`。）

构建还会写出这些重定向（`_redirects`）：

| 来源                                           | 目标                                  |
| ---------------------------------------------- | ------------------------------------- |
| `/{code}/…`，当 code ≠ prefix                  | `/{prefix}/…`（`/en/…` → `/en-US/…`） |
| `/{repoSlug}/…`、`/search`、`/languages`       | 默认语言下的同一路径                  |
| `/{prefix}/{homepageRepo}`                     | `/{prefix}`                           |
| 设置了 `landingPage` 的 `/{prefix}/{repoSlug}` | `/{prefix}/{repoSlug}/{landingPage}`  |

页面的 [Markdown](./build-and-deployment#ai-智能体)（页面 URL 加上 `.md`）也按同样
的方式重定向：`/glint.md` 会前往 `/en-US/glint.md`。`/.md` 会前往 `/` 处页面的
Markdown；如果每种语言都有前缀，则前往默认语言落地页的 Markdown。

没有匹配页面的 URL 会得到它开头那种语言的 404 页面。

在站内点击链接时不会经过这些重定向：客户端直接前往目标页面，不带语言的链接
（例如站点导航里的 `/prism/…`）会停留在读者当前的语言。如果某种语言的 `prefix`
为空，不带前缀的 URL 就是该语言的页面，这样的链接会前往那里。

## 语言选择器

当配置了多于一种语言时，NavBar 会显示一个地球图标。点击它能切换到
所选语言的同一页面，保留仓库和页面路径，并为 `/` 记住这次选择。

如果用户选择的语言下当前页面没有翻译，会落到一个 404（带本地化的
404 外壳）。

下拉菜单先列出当前语言，其余按标签字母顺序排列。站点语言超过 10 个
时，下拉会截断，并链接到下面的全部语言页面。

## 全部语言页面

路由：`/{localePrefix}/languages`（`/languages` 会去默认语言的这个页面）。一个
整页的语言选择器，适合语言多到 NavBar 下拉放不下的站点。下拉菜单的
最后一项始终链接到这里：「更多语言…」，截断后则是「全部语言 (N)」。

页面里语言按大洲分组——通过 `Intl.Locale.maximize().region` 加
`countries-list` 决定大洲归属（亚洲 → 欧洲 → 非洲 → 北美洲 →
南美洲 → 大洋洲 → 南极洲 → 其他）。每个大洲内部按原生标签字母
顺序排序。页面顶部有一个搜索框，可以按标签、代码或 URL 前缀过滤。

每张卡片是一个 FluentUI Card，显示原生名称和 BCP-47 代码。默认语言
带「源语言」徽章。读者当前所在的语言带品牌色背景，且不可点击。URL 上
传 `?page=<repo 相对路径>`，点击卡片就能保持页面路径不变地切换语言
（下拉菜单里的链接正是这样带着 page 跳过来的）。

## 本地化的站点外壳

`src/shared/i18n.ts` 持有 Vellum 控制的所有文案——搜索对话框标签、
"上一页" / "下一页" 导航、提示框默认标题、404 页面，等等。
当前内置英语（`en`）和简体中文（`zh`）的手工字典。

新增第三种语言：

1. 在 `vellum.config.json` 的 `site.locales` 里新增一项。
2. 在 `src/shared/i18n.ts` 里新增一份字典：

```ts
const fr: MessageMap = {
  "ui.search": "Recherche",
  "ui.search.placeholder": "Rechercher dans la documentation",
  // ...
};

const dictionaries: Record<string, MessageMap> = { en, zh, fr };
```

3. 把你的内容翻译到 `docs/fr/` 里。

任何在非英语字典中缺失的 key 都会回退到英语字符串——所以可以先发
一份部分翻译，也不会让 UI 坏掉。

## frontmatter 与 i18n

frontmatter 的 `title` 和 `description` 是内容，不是外壳——
在每种语言各自的文件副本里翻译它们。英语的 frontmatter 永远不会
泄漏到已翻译的页面。

## markdown 中的本地化链接

写成相对文档根的 markdown 链接（例如
`[Getting started](./getting-started)`）会被构建改写，
自动带上当前语言的前缀。所以在 `docs/zh/index.md` 里，这条链接
会解析为 `/zh/repo/getting-started`，而不是 `/repo/getting-started`。

跨仓库的 `@slug/` 链接行为一致：

```md
See [the Prism guide](@prism/getting-started) for OAuth setup.
```

在一个 `zh` 页面上阅读时，它会渲染为指向目标仓库相同语言的链接
（`/zh/prism/getting-started`）。

## 落地页

落地页就是主页仓库的首页，所以和其他页面一样翻译：在主页仓库中添加
`{code}/index.md`。自带的配置就是这么做的——
中文主页见 `local-docs/homepage/zh/index.md`。
