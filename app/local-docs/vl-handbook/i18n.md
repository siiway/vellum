# Internationalisation

Vellum has first-class support for multi-locale documentation. Locales are
configured at the site level and apply across every repo.

## Site-level locale config

```json
{
  "site": {
    "defaultLocale": "en",
    "locales": [
      { "code": "en", "label": "English", "prefix": "" },
      { "code": "zh", "label": "中文", "prefix": "zh" },
      { "code": "ja", "label": "日本語", "prefix": "ja" }
    ]
  }
}
```

- `code` is the locale code (used for i18n lookup and as the default source
  directory of a non-default locale).
- `label` is shown in the language picker.
- `prefix` is the URL segment. An empty string means this locale lives at
  the root of each repo — typically used for the default locale.

A reader on `/zh/repo/getting-started` is reading the `zh` version of
`getting-started` in `repo`.

## Per-repo content layout

The default locale's pages live directly under `docsRoot`. Every other
locale's pages live under `{docsRoot}/{code}/`, named after the locale's
`code` rather than its URL prefix.

```
docs/
  index.md                    # en (default locale)
  getting-started.md
  zh/
    index.md                  # zh
    getting-started.md
  ja/
    index.md
    getting-started.md
```

::: note
You don't have to translate every page. A reader on
`/zh/repo/missing-page` gets a 404, not a fallback to the English page —
keeping the missing-translation cost obvious to the docs maintainer.
:::

### Other layouts

Some repos give every locale its own directory, including the default one.
Map each locale code to its directory with `localeDirs` on the repo:

```json
{
  "slug": "nextbridge",
  "docsRoot": "",
  "localeDirs": { "en": "en", "zh": "zh" },
  "landingPage": "v0.4"
}
```

```
en/
  v0.4/
    index.md                  # /en-US/nextbridge/v0.4
    getting-started.md        # /en-US/nextbridge/v0.4/getting-started
zh/
  v0.4/
    index.md                  # /zh-CN/nextbridge/v0.4
index.md                      # belongs to no locale; not served
```

Files outside every locale's directory belong to no locale and aren't
served. Absolute links written against the directory, such as
`/en/v0.4/rules` in a sidebar, a hero action or a page, resolve inside
the repo.

When the docs root has no real home page, as with docs versioned by
directory, `landingPage` redirects the repo's root URL there:
`/en-US/nextbridge` goes to `/en-US/nextbridge/v0.4`.

## Routing

Every page URL is locale-first:

```
/{localePrefix}/{repoSlug}[/{pagePath}]
```

The build renders each locale's pages from that locale's source directory,
so the same `pagePath` ("getting-started") comes from
`docs/getting-started.md` for `en` and `docs/zh/getting-started.md` for `zh`.
The homepage repo's index is the landing page at `/{localePrefix}`.

`/` has no page of its own. It picks a locale in the browser: the locale the
reader chose before (the `vellum-locale` cookie, set by the language picker),
then the browser's languages, then `defaultLocale`. Without JavaScript it
goes to the default locale.

The build also writes these redirects (`_redirects`):

| From                                      | To                                   |
| ----------------------------------------- | ------------------------------------ |
| `/{code}/…` when code ≠ prefix            | `/{prefix}/…` (`/en/…` → `/en-US/…`) |
| `/{repoSlug}/…`, `/search`, `/languages`  | the same under the default locale    |
| `/{prefix}/{homepageRepo}`                | `/{prefix}`                          |
| `/{prefix}/{repoSlug}` with `landingPage` | `/{prefix}/{repoSlug}/{landingPage}` |

A URL that matches no page gets the 404 page of the locale it starts with.

Links followed inside the site skip these redirects: the client goes straight
to the page they lead to, and a link without a locale (`/prism/…` in the site
nav, say) stays in the reader's locale.

## The language picker

The NavBar shows a globe icon when more than one locale is configured.
Clicking switches to the same page in the chosen locale — preserving the
repo, page path, and any hash.

If the user picks a locale that doesn't have the current page translated,
they'll land on a 404 (with the localised 404 chrome).

The dropdown lists the current locale first, then the rest alphabetically
by label. Once a site has more than 10 locales it truncates and links to
the languages page below.

## The languages page

Route: `/{localePrefix}/languages` (and `/languages` for the default
locale). A full-page locale chooser for sites with more locales than the
NavBar dropdown comfortably holds. The dropdown always ends with a link
here: "More languages…", or "All languages (N)" once it truncates.

Locales are grouped by continent via `Intl.Locale.maximize().region` →
`countries-list` (Asia → Europe → Africa → North America → South America
→ Oceania → Antarctica → Other for codes without country data). Inside
each continent they're sorted by native label. A search input at the top
filters by label, code, or URL prefix.

Each tile is a FluentUI Card showing the native name and the BCP47 code.
The default locale carries a "Source" badge. The reader's current locale
gets a brand-tinted background and is non-interactive. Pass
`?page=<repo-rooted-path>` in the URL and tile clicks swap locale while
keeping the page path (so the dropdown's link lands the reader on the
same page in their chosen locale).

## Locale-aware site chrome

`src/shared/i18n.ts` holds the dictionary for everything Vellum
controls — search dialog labels, "Previous" / "Next" page nav, callout
default titles, the 404 page, etc. Currently ships English (`en`) and
Simplified Chinese (`zh`) hand-curated dictionaries.

To add a third language:

1. Add an entry to `site.locales` in `vellum.config.json`.
2. Add a dictionary in `src/shared/i18n.ts`:

```ts
const fr: MessageMap = {
  "ui.search": "Recherche",
  "ui.search.placeholder": "Rechercher dans la documentation",
  // ...
};

const dictionaries: Record<string, MessageMap> = { en, zh, fr };
```

3. Translate your content into `docs/fr/`.

Any key missing from a non-English dictionary falls back to the English
string — so you can ship a partial translation without breaking the UI.

## Frontmatter and i18n

Frontmatter `title` and `description` are content, not chrome — translate
them in each locale's copy of the file. The English frontmatter never
leaks to a translated page.

## Locale-aware links in markdown

Markdown links written as docs-root-relative paths
(e.g. `[Getting started](./getting-started)`) are rewritten by the build
to include the current locale prefix. So in `docs/zh/index.md`, that link
resolves to `/zh/repo/getting-started`, not `/repo/getting-started`.

Cross-repo `@slug/` links work the same way:

```md
See [the Prism guide](@prism/getting-started) for OAuth setup.
```

renders as a link to the same locale of the target repo (`/zh/prism/getting-started`
when read on a `zh` page).

## The landing page

If `homepageRepo` is a local source, you can localise its landing page by
adding `local-docs/{homepage-slug}/{prefix}/index.md`. The bundled config
does exactly that — see `local-docs/homepage/zh/index.md` for the Chinese
homepage.
